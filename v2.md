# Asapp Electronic — API v2 (Business-Friendly)

> Referencia para implementar integraciones con la API v2 de Asapp Electronic.
> Esta API acepta valores de negocio legibles; nunca se necesitan códigos SRI internos.
>
> Última actualización: 2026-08-28

> ¿Ya integraste con la **[API v1 — JSON con códigos SRI](index.html)**? v2 usa el mismo flujo
> asíncrono y el mismo servicio — solo cambia el formato del request. Ambas versiones conviven,
> no hace falta migrar.

---

## Diferencia con v1

La v1 (`POST /v1/api/comprobantes`) requiere códigos SRI: `tipoDocumento: "01"`, `codigoPorcentaje: "4"`, `formaPago: "01"`. La v2 reemplaza todo eso con valores de negocio. El integrador no necesita conocer ningún código SRI.

---

## Entornos

| Entorno | Base URL |
|---------|----------|
| Staging / QA | `https://electronic-api-dev.asapp.com.ec` |
| Producción | `https://electronic-api.asapp.com.ec` |

El campo `ambiente` dentro del request controla si el comprobante va al SRI de pruebas o producción — **independiente de la URL base usada**.

---

## Autenticación

```
X-Api-Key: asapp_<clave_de_la_empresa>
```

Las keys son independientes por empresa y por entorno. Se generan en el portal Asapp → Configuración → Integración API.

---

## Endpoint único

```
POST /api/v2/api/comprobantes
Content-Type: application/json
X-Api-Key: asapp_<clave>
```

Aplica a los 6 tipos de comprobante. El campo `tipo` del body determina qué documento se emite.

El comprobante se registra, firma y envía al SRI de forma asíncrona. La respuesta inicial devuelve el ID; el estado final se consulta por separado.

---

## Mapeos automáticos

### `tipo` — tipo de comprobante

| Valor en v2 | Alias aceptados | Tipo SRI |
|-------------|-----------------|----------|
| `factura` | `fac`, `01` | 01 |
| `liquidacion_compra` | `lc`, `03` | 03 |
| `nota_credito` | `nc`, `04` | 04 |
| `nota_debito` | `nd`, `05` | 05 |
| `guia_remision` | `gr`, `06` | 06 |
| `retencion` | `ret`, `07` | 07 |

Comparación case-insensitive y trimmed.

### `items[].iva` — tarifa de IVA

| Valor | Descripción | Tarifa |
|-------|-------------|--------|
| `15` | IVA 15% (tarifa vigente 2026) | 15% |
| `0` | IVA 0% | 0% |
| `5` | IVA 5% | 5% |
| `exento` | Exento de IVA | 0% |
| `no_objeto` | No objeto de IVA | 0% |

El valor del impuesto se calcula automáticamente:
`valor = round((cantidad × precioUnitario − descuento) × tarifa / 100, 2)`

### `pagos[].metodo` — forma de pago

| Valor | Alias | Código SRI |
|-------|-------|------------|
| `efectivo` | `cash` | 01 |
| `tarjeta_debito` | `debito` | 16 |
| `dinero_electronico` | `movil` | 17 |
| `tarjeta_credito` | `credito` | 19 |
| `transferencia` | `otros` | 20 |

### `ambiente`

| Valor | Alias | Efecto |
|-------|-------|--------|
| `produccion` | `production`, `producción` | SRI producción — fiscalmente válido |
| `pruebas` | `test`, `qa`, `dev` | SRI pruebas — nunca válido fiscalmente |

### Tipo de identificación del receptor (auto-detectado)

El campo `tipoIdentificacion` no existe en v2. Se detecta automáticamente del número enviado:

| Regla | Tipo detectado |
|-------|----------------|
| Exactamente `"9999999999999"` | Consumidor Final (07) |
| 13 dígitos numéricos | RUC (04) |
| 10 dígitos numéricos | Cédula (05) |
| Cualquier otro formato | Pasaporte / exterior (06) |

## Campos del request

### Campos comunes (todos los tipos)

| Campo | Tipo | Req. | Descripción |
|-------|------|------|-------------|
| `tipo` | string | ✅ | Tipo de comprobante. Ver tabla de mapeos. |
| `ambiente` | string | ✅ | `pruebas` o `produccion` |
| `establecimiento` | string | ✅ | Código del establecimiento. Ej: `"001"` |
| `puntoEmision` | string | ✅ | Código del punto de emisión. Ej: `"001"` |
| `fecha` | string ISO 8601 | ✅ | Fecha de emisión con timezone Ecuador `-05:00`. Ej: `"2026-07-09T10:00:00-05:00"` |
| `secuencial` | number | ❌ | Si se omite, Asapp auto-genera el siguiente número. Si se envía, Asapp valida duplicado. |
| `moneda` | string | ❌ | Default: `"DOLAR"` |
| `propina` | number | ❌ | Propina en dólares. Default: 0 |
| `guiaRemision` | string | ❌ | Número de GR vinculada a una factura. Formato: `"001-001-000000001"` |
| `placa` | string | ⚠️ | Placa del vehículo. **Obligatoria solo para `tipo: "factura"` si la empresa está registrada como operadora de transporte terrestre.** Si falta en ese caso, rechaza con `PlacaRequerida`. Para Guía de Remisión usar `transporte.placa` en su lugar (ver abajo) — este campo raíz no aplica a GR. |
| `infoAdicional` | array | ❌ | Campos adicionales SRI. Cada elemento: `{ "nombre": "...", "valor": "..." }` |

### Objeto `cliente` (Factura, LC, NC, ND)

| Campo | Tipo | Req. | Descripción |
|-------|------|------|-------------|
| `cliente.identificacion` | string | ✅ | RUC, cédula, `"9999999999999"` o pasaporte. Tipo detectado automáticamente. |
| `cliente.nombre` | string | ✅ | Razón social. Para consumidor final cualquier valor — Asapp fuerza `"CONSUMIDOR FINAL"`. |
| `cliente.email` | string | ❌ | Email del RIDE autorizado. Múltiples separados por `\|`. |
| `cliente.direccion` | string | ❌ | Dirección del comprador. |

### Array `items` (Factura, LC, NC, ND)

| Campo | Tipo | Req. | Descripción |
|-------|------|------|-------------|
| `items[].descripcion` | string | ✅ | Descripción del producto o servicio |
| `items[].cantidad` | number | ✅ | Cantidad. Acepta decimales. |
| `items[].precioUnitario` | number | ✅ | Precio por unidad sin IVA |
| `items[].iva` | string | ✅ | Tarifa IVA. Ver tabla de mapeos. |
| `items[].descuento` | number | ❌ | Descuento en dólares absoluto (no porcentaje). Default: 0 |
| `items[].codigo` | string | ❌ | Código del producto. Default: `"SN"` (sin código) |

### Array `pagos` (Factura, LC, NC)

> La Nota de Débito **no lleva pagos** — el SRI lo rechaza. No incluir el array `pagos` para ND.

| Campo | Tipo | Req. | Descripción |
|-------|------|------|-------------|
| `pagos[].metodo` | string | ✅ | Método de pago. Ver tabla de mapeos. |
| `pagos[].total` | number | ✅ | Total pagado con este método (incluye IVA) |
| `pagos[].plazo` | number | ❌ | Plazo de crédito (número). Solo para crédito. |
| `pagos[].unidadTiempo` | string | ❌ | `"dias"` o `"meses"`. Solo para crédito. |

### Campos para NC y ND — documento modificado

| Campo | Tipo | Req. | Descripción |
|-------|------|------|-------------|
| `motivo` | string | ✅ | Motivo de la nota |
| `documentoModificado.tipo` | string | ✅ | Tipo del doc original. Ej: `"factura"` |
| `documentoModificado.numero` | string | ✅ | Número completo. Formato: `"001-001-000000100"` |
| `documentoModificado.fechaEmision` | string ISO 8601 | ✅ | Fecha de emisión del doc original |

| Campo | Tipo | Req. | Descripción |
|-------|------|------|-------------|
| `destinatario.identificacion` | string | ✅ | RUC o cédula del destinatario |
| `destinatario.nombre` | string | ✅ | Razón social del destinatario |

| Campo | Tipo | Req. | Descripción |

La retención no usa `cliente`, `items` ni `pagos`. Todo va en `retencion`.

| Campo | Tipo | Req. | Descripción |
|-------|------|------|-------------|

| `retencion.anio` | number | ✅ | Año del período fiscal |
| `retencion.identificacion` | string | ✅ | RUC o cédula del sujeto retenido |
| `retencion.nombre` | string | ✅ | Razón social del sujeto retenido |
| `retencion.email` | string | ❌ | Email para enviar el comprobante autorizado |
| `retencion.documentosSustento` | array | ✅ | Documentos sustento de la retención |

Cada elemento de `retencion.documentosSustento`:

| Campo | Tipo | Req. | Descripción |
|-------|------|------|-------------|
| `tipoDocumento` | string | ✅ | Tipo del doc. Ej: `"factura"` |
| `numeroDocumento` | string | ✅ | Número. Formato: `"001-001-000000200"` |
| `fechaEmision` | string ISO 8601 | ✅ | Fecha del doc sustento |
| `numeroAutorizacion` | string | ✅ | Número de autorización SRI (49 dígitos) |
| `formaPago` | string | ❌ | Método de pago del doc sustento. Default: `"efectivo"` |
| `retenciones` | array | ✅ | Retenciones aplicadas |

Cada elemento de `retenciones`:

| Campo | Tipo | Req. | Descripción |
|-------|------|------|-------------|
| `tipoImpuesto` | string | ✅ | `"renta"` o `"iva"` |

## Respuesta HTTP 200

```json
{
  "comprobanteId": 1287,
  "claveAcceso": "0907202601179245678900110010010000012871234567819",
  "numeroComprobante": "001-001-000001287",
  "tipoDocumento": "01",
  "estado": "Grabado",
  "mensaje": "Comprobante registrado. Consulte /estado para seguir el flujo SRI."
}
```

- `comprobanteId`: usar para consultar estado
- `claveAcceso`: identificador único SRI de 49 dígitos
- `numeroComprobante`: formato `estab-pto-secuencial`
- `estado`: siempre `"Grabado"` en la respuesta inicial

## Consulta de estado

```
GET /api/v1/comprobantes/{comprobanteId}/estado
X-Api-Key: asapp_<clave>
```

Pollear cada 5–15 segundos hasta estado terminal.

| Estado | Terminal | Significado |
|--------|----------|-------------|
| `Grabado` | No | Registrado, en proceso de firma |
| `Firmado` | No | XML firmado digitalmente |
| `Enviado` | No | Enviado al SRI, esperando respuesta |
| `Recibido` | No | SRI lo recibió, pendiente autorización |
| `Autorizado` | **Sí ✓** | Autorizado por el SRI — documento válido |
| `Devuelto` | **Sí ✗** | Rechazado en recepción SRI |
| `NoAutorizado` | **Sí ✗** | Rechazado en autorización SRI |
| `Timeout` | **Sí ⚠** | SRI no respondió en tiempo máximo |
| `Anulado` | **Sí** | Anulado desde el portal |

---

## Email automático

Cuando el SRI autoriza (`Autorizado`), Asapp envía automáticamente el RIDE (PDF) y el XML al email del receptor. En estados `Devuelto`, `NoAutorizado` o `Timeout` no se envía ningún email.

Múltiples destinatarios: separar con `|` en el campo `email`. Ej: `"a@empresa.com|b@empresa.com"`

## Reglas de negocio automáticas

Asapp aplica estas reglas internamente — el integrador no necesita conocerlas:

1. **Consumidor Final — razón social forzada**: cuando `cliente.identificacion == "9999999999999"`, Asapp fuerza `razonSocial = "CONSUMIDOR FINAL"` en el XML independientemente del `nombre` enviado. El SRI exige esta cadena exacta en mayúsculas.

2. **Consumidor Final — límite $50**: facturas a consumidor final con total > $50.00 son rechazadas antes de procesarse con error `CONSUMIDOR_FINAL_LIMITE_EXCEDIDO`. Se debe incluir la identificación real del comprador.

3. **Secuencial duplicado**: si se envía `secuencial` y ya existe un comprobante con ese número en el mismo tipo, ambiente y empresa, Asapp retorna `SECUENCIAL_DUPLICADO` con la ClaveAcceso del comprobante existente. Si no se envía `secuencial`, Asapp genera el siguiente automáticamente.

4. **Nota de Débito sin pagos**: el SRI no admite `<pagos>` en el XML de Nota de Débito. Asapp lo omite del XML siempre.

5. **Código de producto por defecto**: si `items[].codigo` viene vacío o no se envía, Asapp usa `"SN"`. El SRI requiere longitud mínima 1.

6. **Fechas en timezone Ecuador**: siempre enviar con offset `-05:00`. El SRI opera en hora Ecuador y discrepancias pueden causar rechazo.

7. **RUC Proveedor (campo reservado en `infoAdicional`)**: si la empresa tiene configurado un RUC de proveedor de facturación electrónica, Asapp agrega automáticamente un elemento `{ "nombre": "RUC Proveedor", "valor": "..." }` a `infoAdicional`. Si el request ya trae un elemento con ese `nombre`, Asapp lo **sobrescribe** — nunca se duplica ni se respeta el valor enviado por el integrador.

## Errores de la API

```json
{
  "error": "CONSUMIDOR_FINAL_LIMITE_EXCEDIDO",
  "mensaje": "Las facturas a Consumidor Final no pueden superar $50.00 (total: $75.30). Incluya la identificación del comprador."
}
```

| HTTP | Código | Causa | Acción |
|------|--------|-------|--------|
| 400 | `TIPO_INVALIDO` | Valor en `tipo` no reconocido | Usar valores de la tabla de mapeos |
| 400 | `IVA_INVALIDO` | Valor en `items[].iva` no reconocido | Usar `15`, `0`, `5`, `exento`, `no_objeto` |
| 400 | `METODO_PAGO_INVALIDO` | Valor en `pagos[].metodo` no reconocido | Usar valores de la tabla de mapeos |
| 400 | `AMBIENTE_INVALIDO` | Valor en `ambiente` no reconocido | Usar `pruebas` o `produccion` |
| 400 | `CONSUMIDOR_FINAL_LIMITE_EXCEDIDO` | Factura a consumidor final con total > $50.00 | Incluir identificación real del comprador |
| 422 | `PlacaRequerida` | Factura sin `placa` y la empresa es operadora de transporte | Incluir `placa` a nivel raíz del request |
| 409 | `SECUENCIAL_DUPLICADO` | Número ya existe en ese ambiente | No reemitir — consultar la ClaveAcceso devuelta en el error |
| 401 | — | API Key ausente o inválida | Verificar header `X-Api-Key` |
| 404 | — | Establecimiento o punto de emisión no existe | Verificar en el portal Asapp |
